# PyCrypto Studio (Python + PySide6)

Python-версия крипто-утилиты: **AES, RSA, SHA-256, ECDSA** (библиотека pycryptodome) и российские стандарты
**Магма, Стрибог, Кузнечик** (реализованы вручную: таблицы замен, матрицы, константы). Вкладки идут в том же
порядке, что и в версии на C++/Qt. Все данные (хеши, ключи, IV, начало шифртекста) выводятся в **двоичном виде**.

## О библиотеке: pycrypto → pycryptodome

Оригинальный `pycrypto` заброшен с 2013 года, не устанавливается на современный Python (3.12+) и не содержит
ECDSA. Именно она используется в проекте.

## Установка

**Arch / Omarchy (виртуальное окружение, рекомендуется):**
```bash
cd PyCryptoStudio
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```
Либо системными пакетами: `sudo pacman -S python-pyside6 python-pycryptodome`, затем `python main.py`.

**Windows / macOS:** `pip install -r requirements.txt`, затем `python main.py`.
## Структура

```
main.py              — точка входа
core/                — вся криптография, без привязки к интерфейсу
  aes.py rsa.py sha.py ecdsa.py          — pycryptodome
  magma.py kuznyechik.py streebog.py     — ГОСТ, вручную
  magma_sbox.py gost_pi.py streebog_tables.py — таблицы замен, π, матрица A, константы (из RFC)
  cbc.py block_cipher_files.py           — режим CBC и файловые операции для Магмы/Кузнечика
  formatting.py logger.py files.py ...   — двоичный вывод, журнал, вспомогательное
gui/                 — интерфейс PySide6 (страница на файл)
tests/               — тесты
```

## Совместимость с версией на C++

Форматы файлов и ключей совпадают «1 в 1»: файлы `.aes`, `.rsa`, `.magma`, `.kuz`, подписи `.sig`, ключи RSA
(PKCS#8 / SubjectPublicKeyInfo) и ECDSA, хеши SHA-256 и Стрибог. Зашифровав файл в одной программе,
его можно расшифровать в другой (проверено в обе стороны, включая ключи, созданные Crypto++ и pycryptodome).

## ГОСТ-алгоритмы

Реализованы по RFC 8891 (Магма), RFC 7801 (Кузнечик), RFC 6986 (Стрибог); таблицы перенесены из RFC.
Проверка — по тестовым векторам этих RFC (`tests/test_vectors_rfc.py`): преобразования, ключевое расписание,
шифрование/расшифровка блока, константы, хеши для 256 и 512 бит. Таблица π у Кузнечика и Стрибога одна.
CBC + PKCS#7, случайный IV в начале файла. Байты хеша Стрибога выводятся в порядке памяти (как у OpenSSL);
в RFC 6986 те же значения записаны как большое число, то есть в обратном порядке байт.

**Скорость.** Библиотечные AES/SHA-256 работают со скоростью сотен МБ/с, а ГОСТ на чистом Python —
примерно 0,4–1,2 МБ/с (файл в 10 МБ — десятки секунд). Операции идут в фоновом потоке, окно не зависает.
Реализация учебная и не является сертифицированным средством защиты.

## Тесты

```bash
python tests/test_vectors_rfc.py     # векторы RFC для Магмы, Кузнечика, Стрибога
python tests/test_files.py           # шифрование/расшифровка файлов, ECDSA, ошибки
```

Заметка для отчёта: CBC не обеспечивает целостность — при неверном ключе примерно в 1 случае из 256
паддинг «случайно» окажется корректным и вместо ошибки получится мусор. Для защиты от этого используют AES-GCM.
